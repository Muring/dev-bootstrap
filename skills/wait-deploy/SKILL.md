---
name: wait-deploy
description: 이미 시작된 GitHub 배포·CI의 commit status와 check run을 한 프로세스에서 기다리고 결과를 요약한다. 배포 실행은 하지 않는다.
---

Claude `/wait-deploy`, Codex `$wait-deploy`. 함께 전달한 입력을 대상 저장소·커밋·상태 이름으로 해석한다.
사용자가 작업 중인 저장소에서 이 스킬의 스크립트를 실행한다. `gh`의 기존 인증을 사용한다.

```bash
python3 <이-스킬-경로>/scripts/wait_deploy.py --context Vercel --timeout 600 --json
```

`--repo owner/repo`, `--sha <40자리 SHA>`를 생략하면 현재 저장소/HEAD를 한 번 고정한다. `--context`는 실제 확인한 status/check 이름이며 반복 지정할 수 있다. 생략하면 조회된 전체 항목을 기다리지만 아직 등록되지 않은 작업까지 성공했다고 해석하지 않는다. 특정 배포를 기다릴 때는 반드시 그 이름을 지정한다.

스크립트가 10~45초 backoff로 조회하고 상태 변화만 stderr, 최종 결과만 stdout에 출력한다. 같은 커밋에 `sleep → gh api`를 모델 호출로 반복하지 않는다. 도구가 실행 ID를 반환하면 30~60초 기다려 확인하고 필요한 진행 상황만 사용자에게 알린다. 임의의 짧은 빈 폴링을 반복하지 않는다.

종료 코드: 성공 0, 실패 1, 제한시간 2, 인증·API·실행 오류 3. 빈 상태/필수 항목 누락은 성공이 아니다. 실패 시 상세 링크를 확인하고 원인을 보고한다. 인증 오류를 무한 재시도하지 않는다.
성공은 선택한 GitHub 상태의 성공이다. 실제 배포 화면 확인은 대상 URL·배포 커밋을 맞춘 뒤 별도로 수행한다. 이 명령은 push·재배포·취소를 하지 않는다.
