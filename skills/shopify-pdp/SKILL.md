name: shopify-pdp
description: Build Shopify product-description HTML by placing missing live text over supplied background images, using Illustrator AI files and finished JPGs as the layout reference. Use for this image-backed PDP workflow, not whole-theme redesigns.
---

Use this workflow when the user supplies a product source directory containing `.ai`, finished `.jpg`, and `images/`.

Before creating or editing product files, follow [product selection](references/product-selection.md). Accept a product handle and natural-language options after `$shopify-pdp`. An explicit request for all current PDPs selects them all. Otherwise, with no product specified, list the current library’s source products and ask the user to select one; do not silently reuse the previous product. Resolve existing-output intent and missing verification URLs as described there. This is an agent conversation workflow, not a shell argument parser.

Resolve source and output directories first. If the requested path does not exist, ask before substituting another path. Keep another agent's output and the source files unchanged. Ask about missing content, access, or materially ambiguous choices instead of inventing copy.

1. Inventory background dimensions and compare each image with the finished JPG. **Text already printed in a background wins, including when it differs from the AI or finished JPG. Add only missing text.** Keep an explicit list of image-only sections.
2. Read PDF-compatible AI text geometry, fonts, colors and transforms. Do not extract embedded photos; use the supplied images without modifying them. Some visible lettering is outlined and absent from text extraction: inspect the finished JPG as well. Original font metadata is analysis provenance only; do not export fonts for the PDP.
3. Register every background to its corresponding reference region. Export dimensions may differ by a few pixels from the artboard. Store coordinates in a reviewable `layout.px.json` with original artboard width, per-image reference origin, and per-text source provenance.
4. Build a standalone description fragment using HTML text, scoped CSS, and original images. Convert all overlay geometry, font sizes, spacing, borders and radii from px to `cqi` against the outer inline-size container. Round every emitted `cqi` value to at most one decimal place (e.g. `17.83057cqi` → `17.8cqi`); keep original px evidence at full precision and round only at CSS output. The outer maximum width is the intentional pixel cap. Keep image width/height attributes to reserve intrinsic aspect ratio. Do not nest another query container in a section.
5. Use BEM with block `pdp-product`, elements such as `pdp-product__text` and `pdp-product__title`, and a product-specific `pdp-product--HANDLE` modifier. Scope CSS below that modifier. Establish reference alignment and typography from the original AI/JPG before applying shared styles. The semantic scale in scripts/typography.mjs is a reusable starting point, not a reason to change a reference layout. Share values only after confirming that they fit the original text regions; record measured differences as typography_fit (see references/implementation.md). Factor repeated typography into shared BEM role classes and use audited text_groups to wrap fragments of the same sentence/heading into one semantic paragraph/heading. Do not merge independent labels merely because they are adjacent. Emit readable CSS with two-space property indentation for structural rules and `/* base */`, `/* common */`, then `/* section 01 */` comments in image order. Give sections `pdp-product__section--01` modifiers and match HTML section comments. Use semantic BEM elements such as title, point, edge-label and footnote with section-local numbered modifiers for individual styling; Emit no data-* attributes. Keep source IDs and grouping metadata in the px layout; validators resolve text via existing section and element classes. Short typography/position override rules with at most five declarations may stay on one spaced line, as in the user’s example; do not minify the whole stylesheet. Keep per-section rules limited to geometry and actual differences. Inherit the site's globally loaded Pretendard. Do not emit any `font-family` (including `inherit`), `@font-face`, font shorthand, font-related CSS variables, inline font declarations, font loaders, or base64 font data in description/preview artifacts. Reset margins/type styling without breaking inherited font selection (e.g. `all: unset` followed by explicit non-family resets). No product font subsets or runtime positioning JavaScript.
6. Every section needs a meaningful direct-child `h2`: reuse visible headings or supply an audited hidden title using `pdp-product__sr-only`. Link the section with `aria-labelledby`; hidden titles must remain accessible and must not duplicate visible copy. Position and box size use top/right/bottom/left and width/height; never use scale/translate/matrix/skew to fit text, nor emit rotate(0deg). Preserve only nonzero rotations that belong to the source design. Fit natural Pretendard glyphs with font size, tracking, line breaks and explicit coordinates, not stretched glyphs. Distinguish PDF baseline/ink evidence from a CSS line box.
7. Render at source width and mobile widths. Compare every section directly with the supplied JPG, including lower portions of long sections and paragraph alignment. Validate immutable reference_box anchors independently of the previous HTML. A before/after equality test only proves regression equivalence and must never be used as design acceptance. Check focusing on missing/duplicated copy, baseline, line breaks, ink bounds and image seams. Do not report visual identity based only on successful DOM measurements.
8. Test the supplied Shopify `?view=description` page. For pre-upload validation, temporarily replace only its description container in the browser and fulfill background requests from local files. This is a browser-only test; distinguish it from a saved product description. Compare the same content width with standalone rendering, check all fonts/images, bounds, and host heading styles. Ask for access if redirected to a password page. Do not alter an unrelated template to obtain a preview.
9. Deliver `description.html`, `preview.html`, the px source layout, validation evidence, and a CDN filename-to-URL map. Never invent CDN URLs. Verify map completeness and HTTPS before generating upload-ready HTML. Uploading images or saving product/theme changes requires the user's authorization for those actions.

Use the bundled executable [pdp](pdp) and [scripts](scripts/) for reusable operations. Resolve its path relative to this SKILL.md; never look for tools inside an old product directory. The scripts, Python environment and Node/browser dependencies are independent of product output folders. Read [references/commands.md](references/commands.md) for setup, command options, and the manifest format, and [references/implementation.md](references/implementation.md) for baseline/rotation details.

`$shopify-pdp` loads this workflow; it is not a shell alias that blindly runs every script. The agent inspects AI/JPG evidence and audits missing text, then invokes the bundled commands with explicit source and project paths. Do not claim automatic design fidelity before that visual review. Initial manifests are marked `reviewed: false` and cannot be built until the audit is complete.

When organizing multiple products, use one library with `sources/PRODUCT-HANDLE/` for original AI/JPG/background files, `products/PRODUCT-HANDLE/` for generated work, an optional historical font archive, and a generated root `index.html`. Register a library with `pdp library-init --root DIR`; initialize each product inside its products directory. Reuse the same product directory for revisions. Keep existing unrelated source folders and other agents’ outputs untouched unless their migration is explicitly requested.

Use the toolkit’s source-image links: `init` links original backgrounds instead of copying them. The comparison page links original JPGs. After build/verification, run `pdp index --root LIBRARY`. `cdn-map.json`, when present, is the default build mapping; preview.html uses original local images. Preview files deliberately have no font loader; accurate typography is tested in a browser-only host environment using the site's existing global stylesheet. Build and verify require a reachable selected-product verification URL with global Pretendard; do not silently measure a fallback font.

Store only product-specific links, layouts and generated artifacts in the product project. Keep shared implementation in this skill. Legacy font extraction/subsetting/adoption commands are disabled with explanatory errors; source font inspection remains available. Existing analysis history and revisions are preserved unless cleanup is explicitly requested; remove current font references/resources only after checking historical dependents. Do not delete original AI/JPG files or fonts needed by preserved records.

Typical invocation: `$shopify-pdp 원본 /path/to/product 출력 /path/to/product-pdp 검증URL https://store/products/handle?view=description`.

For an authorized source migration, preserve original file names and bytes, update project source paths, image/reference symlinks and reference maps, then verify links and rebuild. Original image subdirectory names may differ between products; inspect them before initialization.

Emit a CSS section comment only when that section has CSS rules; image-only sections retain their HTML section and accessible heading but have no empty CSS group. During cleanup, audit empty comment groups, unused/duplicate CSS rules, text-group separators, and source-run completeness; line count alone is not acceptance.

Every CSS `/* section NN */` comment must have exactly one blank line above and below it, including after a compact single-line rule. Normalize this spacing after formatting; never attach a section comment directly to the previous rule.

Audit repeated property sets, not just identical complete rules. Move repeated shape background, border, radius and shared height into the section’s shape base; instance modifiers contain coordinates, width and actual differences. Do not redeclare initial margin/padding/border/background/shadow values already supplied by the scoped all: unset reset. Keep explicit inherited-property resets and genuine overrides where needed. For CSS-only cleanup, compare before/after pixels and shape/text geometry under the host font and hostile unscoped styles; text-only measurements cannot validate backgrounds or borders.

Preserve alignment intent: left-aligned copy keeps its original start edge; centered text keeps the source center; right-aligned text keeps its end edge. Never infer centering solely because a text box lies near the page center, and never replace original ink bounds with a recentered/fitted box. In particular, inspect scent-note paragraphs for inconsistent indentation and fixed callouts for overlap with printed arrows or borders. When browser computed letter-spacing is normal, normalize it to 0px before Canvas measurement; assigning normal to Canvas silently retains the previous tracking and invalidates ink-bound checks.

## Focused iteration

Claude `/shopify-pdp` and Codex `$shopify-pdp` use this same toolkit. For a small section correction, run `pdp verify --project DIR --sections 2,5 --summary`; it measures selected text geometry and captures selected sections, while retaining global structure/policy checks. The result is explicitly partial and goes to `validation/partial/2-5/report.json`, leaving the full report separate. Use `pdp audit --project DIR --summary` for an offline structure check. Read the detailed report only for failures. Shared CSS, image order, font or layout changes need full verification; before delivery always run `pdp verify --project DIR --summary` at all required widths and review source/mobile imagery. A prior full report is only evidence for its recorded inputHash and time.
