---

Claude `/session-brief`, Codex `$session-brief`. 함께 전달한 입력은 인계할 작업과 강조할 제약이다.
현재 세션에서 이미 확인한 사실을 사용한다. 전체 history를 다시 읽거나 관련 없는 코드를 재탐색하지 않는다.

```bash
python3 <이-스킬-경로>/scripts/session_brief.py --repo /작업/저장소 --json
```

기본 `--base HEAD`는 미커밋 변경을 보여준다. 이번 작업의 시작 커밋을 알면 `--base <SHA>`로 완료한 변경도 포함한다. 경로·해시만 읽으며 파일 내용은 출력하지 않는다. `--limit`을 넘는 파일은 개수와 잘림 여부를 알린다.

인계문은 대체로 15~25줄 안에서 다음 정보를 담는다. 판단에 필요한 예외가 있으면 늘릴 수 있다.
- 목표와 사용자 제약, 이미 허용한 범위
- 확정 결정과 이유, 변경 파일의 역할(전문 복사 대신 경로)
- 실제 실행한 검증과 결과·근거 경로, 미검증 영역
- 남은 작업, 막힌 조건, 다음에 실행할 구체적 행동
- 저장소/worktree, HEAD·기준 커밋, dirty 상태·fingerprint

완료·가정·미해결을 구분하고 토큰 절약을 위해 중요한 제약을 지우지 않는다. 새 세션에서는 HEAD·dirty·fingerprint부터 대조하고 달라진 부분만 다시 확인한다. fingerprint는 의존성·ignored 파일·외부 상태까지 동일함을 증명하지 않으므로 테스트 성공을 자동 재사용하지 않는다.
인계문은 대화에 제공한다. 사용자가 파일 저장을 요청하면 지정 위치에 저장한다. 새 세션 생성·기존 세션 종료·다른 에이전트 전달은 별도 사용자 요청 범위에서만 한다. Orca 세션 전달 요청은 orca-cli를 사용한다.
