name: verify-changes
description: 현재 변경과 영향 경로에 맞는 기존 회귀 검사를 선택해 실행하고 실패 요약을 보고한다. 프로젝트 전체 코드 점검은 code-audit를 사용한다.
---

Claude `/verify-changes`, Codex `$verify-changes`. 함께 전달한 입력은 기준 커밋·검사 이름·검증할 동작이다.
대상은 사용자가 작업 중인 저장소다. 전체 코드 검토 요청이면 `code-audit`를 사용하며 이 명령으로 대체하지 않는다.

1. 관련 프로젝트 지침과 `.agent-checks.json` 및 그 명령이 호출하는 스크립트를 필요한 범위에서 확인한다. 이미 확인했고 내용이 같으면 다시 읽지 않는다. 네트워크·DB 쓰기·배포·자동수정 등은 현재 요청의 권한 범위에 있어야 한다.
2. 선택 결과를 확인하고 실행한다. `--base`는 기준 커밋부터 현재 작업트리까지이며 staged·unstaged·untracked를 포함한다. 필요하면 `--check <이름>`을 반복 지정한다.

```bash
python3 <이-스킬-경로>/scripts/verify_changes.py --repo /프로젝트 --base HEAD --json
python3 <이-스킬-경로>/scripts/verify_changes.py --repo /프로젝트 --base HEAD --run --json
```

`--all`은 **등록된 회귀 검사 전체**이며 프로젝트 전체 코드 감사가 아니다. 설정이 없으면 기존 package scripts/테스트 설정을 좁혀 찾아 사용한다. 실행 성공을 위해 임의로 설정 파일을 생성하거나 테스트를 제거하지 않는다. 새 검사 등록이 작업 범위에 있으면 [설정 형식](references/checks.md)을 사용한다.

실행기는 로그를 임시 디렉터리에 저장하고 요약·실패 꼬리·전체 로그 경로만 반환한다. 성공 결과를 캐시하지 않는다. 실패하면 해당 로그만 읽고, 검사 중 작업트리가 바뀌면 변경 사실을 확인한다. `no-checks`는 통과가 아니다. 자동 경로 선택이 간접 의존성 전체를 증명하지 않으므로 잠금 파일·공용 설정·공용 모듈 변경은 영향 범위를 확인해 검사를 넓힌다.

UI 확인이 필요하면 [브라우저 검증](references/web.md)을 읽는다. 테스트 성공·정적 확인·실제 화면 확인을 구분해 짧게 보고한다. 관련 없는 전체 소스·성공 로그를 다시 출력하지 않는다.

실행기는 함께 배포되는 `session-brief/scripts/worktree.py`를 읽기 전용 Git 조회에 사용한다. 두 스킬은 같은 콘텐츠 버전으로 설치한다.
