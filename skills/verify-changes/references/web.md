# 화면 검증 시작점

먼저 한 번 확인한다: 대상 저장소/worktree와 커밋, 로컬/배포 URL, 확인할 화면·상태, 필요한 인증, 서버 실행 여부. 사용자가 이미 준 값은 다시 묻지 않는다. 로컬 코드 변경을 이전 배포 화면에서 확인하지 않는다.

Orca 환경에서는 설치된 orca-cli 스킬을 읽고 현재 프로젝트의 기존 탭·URL·로그인된 화면을 먼저 확인한다. 인증 값이나 쿠키를 추출하지 않는다. 기존 탭이 유효하면 재사용한다. 다른 작업의 탭을 임의로 이동시키지 않는다. 현재 CLI의 브라우저 가이드를 사용하고 오래된 명령을 추측하지 않는다.

Orca를 사용할 수 없는 경우에만 프로젝트에 맞는 기존 대안을 사용한다. 사용자의 로그인 상태가 다른 브라우저에도 있다고 가정하지 않는다. 서버는 기존 프로세스와 실제 포트를 확인한 뒤 필요한 경우에만 시작한다.

변경한 영역과 필요한 화면 크기부터 확인하고, 공유 스타일·라우팅 변경이면 영향받는 흐름으로 범위를 넓힌다. 로딩 스켈레톤·빈 상태·오류 상태는 실제 그 상태를 만들어 본다. 화면 전체 스크린샷을 매 단계 반복하기보다 영역·DOM/스타일 수치·필요한 스크린샷을 선택한다. 최종 사용자 흐름 검증은 생략하지 않는다.

보고에는 실제 URL과 확인한 상태·화면 크기·남은 한계만 적는다. 임시 미리보기, 브라우저 내 HTML 교체, 실제 배포 확인을 구분한다. 통과한 검사와 무관한 기능까지 정상이라고 말하지 않는다.
