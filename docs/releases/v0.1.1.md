# DevBootstrap-0.1.1-x64.exe

커맨드·스킬을 EXE에서 분리했습니다. 설치 또는 업데이트 확인 시 GitHub main의 커밋을 확인하고, 그 커밋의 파일만 검증해 적용합니다.

## 설치와 업데이트

1. Assets에서 `DevBootstrap-0.1.1-x64.exe`를 받아 Windows 로컬 폴더에서 실행합니다. Git clone은 필요 없습니다.
2. 새 PC는 환경 확인 → 설치 구성 → 변경 내용 확인 → 설치 → 로그인·연동 순서로 진행합니다.
3. 기존 PC는 설치 구성에서 Claude 스킬·커맨드와 Codex 공용 스킬 대상을 선택한 뒤 **커맨드 · 스킬 업데이트 → 업데이트 확인 → 확인한 버전 적용**을 사용합니다.
4. 새 Claude·Codex 세션을 시작합니다.

0.1.0 사용자는 이번 EXE를 한 번 새로 받아야 합니다. 이후 커맨드·스킬 내용 변경은 GitHub에 push한 뒤 앱에서 업데이트하면 됩니다. 설치 코드나 UI 변경은 새 EXE가 필요합니다.

## 변경 내용

- 일반 `skills/<name>/SKILL.md`를 원본으로 유지하고 Claude 명령과 Codex 스킬이 같은 파일을 읽습니다.
- Codex 공용 스킬을 독립 선택 항목으로 추가했습니다. MuRing 구성에서 Recommended입니다.
- 콘텐츠 전용 업데이트는 sudo와 개발 도구 재설치 없이 실행합니다.
- 커밋 고정, Git blob 해시 검증, 이전 콘텐츠 백업, 적용 실패 복구와 중복 실행 방지를 추가했습니다.
- 기존 0.1.0 runtime 링크를 백업 후 전환합니다. 다른 방식으로 만든 기존 경로와 충돌하면 보존하고 중단합니다.
- 비대화형 설치에서 콘텐츠를 선택하면 JSON에 검토한 `contentCommit`이 필요합니다. 기존 콘텐츠 미선택 구성은 그대로 사용할 수 있습니다.
- README와 배포 가이드에 최초 설치, 콘텐츠 업데이트, 다음 EXE 배포 절차를 구분했습니다.

## 검증과 한계

콘텐츠 업데이트 테스트 10개, 구성 테스트 5개, UI 테스트 4개, 설치 순서·셸 설정·KB 회귀 테스트를 통과했습니다.
실제 GitHub에서 임시 홈으로 다운로드·적용하고 Claude/Codex 원본 일치를 확인했습니다.
Windows helper·WSL 인자 전달과 패키징된 Windows 앱의 preload·IPC·실제 WSL 검사 및 원격 콘텐츠 미리보기를 확인했습니다.

서명되지 않은 초기 검증판(Pre-release)입니다. 신규 Windows에서 WSL 설치·재부팅·Ubuntu 생성부터 전체 설치하는 검증은 아직 완료하지 않았습니다. 검증된 원본이 없어 Orca 패치 실환경 회귀 검증도 남아 있습니다.

로그: `%LOCALAPPDATA%\dev-bootstrap`. 콘텐츠 업데이트 결과는 `content-<시간>/result.json`, Ubuntu 콘텐츠 백업은 `~/.local/share/dev-bootstrap/content/backups/`에 있습니다.
